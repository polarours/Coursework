# 04 · 正确性与复杂度 / Correctness & complexity

## 复杂度对照 / Complexity table

| 操作 | LinkedListDeque61B | ArrayDeque61B |
|---|---|---|
| addFirst / addLast | O(1) | 均摊 O(1)（偶发 resize O(n)） |
| removeFirst / removeLast | O(1) | 均摊 O(1) |
| get(i) | O(i) | **O(1)**（取模直达） |
| getRecursive(i) | O(i)（栈深 O(i)） | O(1)（迭代实现） |

> **English:** The table itself is the lesson: linked lists pay per-hop for gets, arrays pay amortized for resizes — proj1b's spec makes you feel the tradeoff the textbook describes.

## 均摊分析 / Amortized analysis

翻倍扩容：从 1 到 n 总搬运成本 ≤ 2n，均摊 O(1)。减半缩容同理。**坑**：如果在占用恰好 1/2 时缩容，交替 add/remove 会抖动（thrashing）成 O(n) 每操作——这正是 CS61B 规格选 1/4 阈值的原因。

> **English:** Shrinking at exactly 1/2 usage would make alternating add/remove cost O(n) each (thrashing); the 1/4 threshold plus the 16 floor kills the oscillation.

## 正确性验证手段 / How correctness was verified

- get 与 getRecursive 全索引一致性断言 / get == getRecursive at all indices.
- 回绕测试：10 元素触发扩容后，两端交替增删 8 次，`toList` 序列仍精确 / wraparound exercised after resize.
- 缩容后行为不变：64 增 60 删，剩 4 个元素的顺序与 get 全对 / shrink preserves order.
- GuitarString 能量：500 步后 100 样本平方和下降但不归零 / energy decays but survives.
