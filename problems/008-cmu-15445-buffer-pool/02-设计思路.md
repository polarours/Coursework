# 02 · 设计思路 / Design rationale

## 整体架构 / Architecture

```text
 上层请求 FetchPage(p0)
        │
   page_table[p0]? ──命中──▶ pin++，更新 LRU
        │未命中
   _find_victim()：空闲页框优先；否则 pin_count==0 的 LRU 页框
        │
   _free_frame()：脏页写盘 → 清页表/LRU → 读入新页
```

> **English:** The `page_table` maps logical page IDs to physical frame indices; LRU is tracked by an OrderedDict where the front is oldest. Keeping these two structures consistent is the whole job.

## 关键决策 / Key decisions

| 决策 / Decision | 选择 / Choice | 理由 / Why |
|---|---|---|
| 页框标识 / Frame id | 初始化时绑定的 index 字段 | 教学版曾因动态属性补丁导致混乱，改为显式字段 / explicit field avoids dynamic-attribute hacks |
| LRU 实现 | OrderedDict，受益时 move_to_end | O(1) 更新 / O(1) touch |
| victim 策略 | 空闲优先，再 LRU 中 pin_count==0 | 保护被使用页 / protects in-use pages |
| 写回时机 / Writeback | 淘汰脏页时 + 显式 flush | 保证持久性 / durability |

## 备选方案 / Alternatives

- Clock（二次机会）算法：更接近真实 DB，但 LRU 更直观。
  *Clock is closer to real DBs; LRU is more intuitive.*
