# 05 · 调试与测试 / Debugging and testing

## 测试环境 / Test environment

Python 3.14.9 / Arch Linux / `python3 tests/test_buffer_pool.py`

## 真实输出 / Real output

```text
[bpm] new_page -> 0,1,2; stats={'frames_used': 3, 'pinned': 3, 'dirty': 3, 'disk_pages': 0}
[bpm] after unpin: stats={'frames_used': 3, 'pinned': 0, 'dirty': 3, 'disk_pages': 0}
[bpm] LRU order (frame idx) = [1, 2, 0]
[bpm] new_page with full pool -> 3; stats={'frames_used': 3, 'pinned': 1, 'dirty': 3, 'disk_pages': 1}
[bpm] flush(p0)=True; disk pages=[0, 1]
[bpm] pinned page 0 survived evictions: True; stats={'frames_used': 3, 'pinned': 2, 'dirty': 2, 'disk_pages': 8}
[bpm] delete_page(0)=True; stats={'frames_used': 2, 'pinned': 1, 'dirty': 2, 'disk_pages': 8}
--- PASS: test_buffer_pool
ALL TESTS PASSED
```

## 输出解读 / Reading the output

- `LRU order = [1,2,0]`：访问 p0 后它变成 MRU，p1 成为 LRU；随后新页确实淘汰了 p1。
- `disk_pages` 从 0 增到 8：脏页淘汰与 pin 保护测试中的多次写回。

## 失败案例与排查 / Failures and debugging

| 症状 / Symptom | 原因 / Cause | 修复 / Fix |
|---|---|---|
| LSP 报 Frame.index 属性未知 | 初版用动态属性补丁 `Frame.index = 0` | 改为 dataclass 显式字段 index，初始化绑定 |
| 测试依赖手动绑定 frame index | 初版测试脆弱，手动设 f0.index | 重写测试，完全通过公开 API，不再碰内部字段 |

> **English:** All tests passed. Touching p0 made it MRU (LRU order [1,2,0]), so the next allocation evicted p1 while p0 and p2 stayed resident. flush(p0) wrote the exact bytes to the simulated disk, and a pinned page survived six further allocations — direct evidence that _find_victim skips pinned frames.
