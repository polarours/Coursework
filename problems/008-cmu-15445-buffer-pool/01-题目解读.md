# 01 · 题目解读 / Understanding the problem

## 需求概述 / Requirements

CMU 15-445 的 Buffer Pool Manager 让学生实现数据库存储引擎的核心：在有限内存中缓存磁盘页。
CMU 15-445's buffer pool lab implements the core of a DB storage engine: caching disk pages in limited memory.

1. **页框管理 / Frame management**：固定数量页框，维护 page_id → frame 的映射。
2. **pin/unpin**：被 pin 的页不能被淘汰（正在被上层使用）。
   *Pinned pages cannot be evicted (in use by upper layers).*
3. **替换策略 / Replacement policy**：LRU，优先淘汰最久未使用的 unpinned 页。
4. **脏页写回 / Dirty writeback**：被修改的页淘汰前必须写回磁盘。
   *Dirty pages must be flushed to disk before eviction.*

> **English:** The pin mechanism is what makes a buffer pool correct: without it, a page being read could be evicted mid-operation. This is the key difference from a simple cache.

## 边界条件 / Edge cases

- 池满时新页必须淘汰 LRU 页 / Full pool → evict LRU.
- 所有页都被 pin → 无 victim，返回失败 / All pinned → no victim, fail.
- 脏页淘汰前写回磁盘 / Dirty page → writeback before eviction.

## 验收 / Acceptance

- [x] 3 页框池，分配 0/1/2 后池满
- [x] 访问 p0 后新页淘汰 LRU 的 p1，保留 p0/p2
- [x] 脏页 p0 flush 到磁盘，数据一致
- [x] pin 住的页经历 6 次分配仍存活
- [x] delete_page 清理页表
