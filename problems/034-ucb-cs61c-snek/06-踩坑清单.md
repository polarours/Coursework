# 06 · 踩坑清单 / Pitfalls

## 1. 只 free 外层指针 / Freeing only the outer pointer

```c
free(game->board);          /* 错：泄漏 18 行 */
```

`board` 是 `char **`，每行都是独立 `malloc`。必须先循环 free 每一行，再 free 指针数组。

反过来（先 free 指针数组再 free 行）同样错——那会丢失行指针，而且 free 之后不能再解引用。

## 2. 单测重复链接 game.c / Double-linking game.c

```
multiple definition of `create_default_game'
```

`unit_tests.c` 第 8 行 `#include "game.c"`（为了测 `static` 函数）。命令行再写 `game.c` 就重复定义。

正确依赖：`unit_tests.c + snake_utils.c + asserts.c`。

## 3. 在错误的目录跑单测 / Running unit tests from the wrong directory

单测用相对路径 `tests/01-simple-in.snk` 打开棋盘。在 `tests/.build/` 里运行时，这个路径不存在，`fopen` 返回 `NULL`。

如果 `read_line` 没检查 `fp == NULL`，就会直接在 `fgets(NULL)` 上段错误——本项目第一版就是这样崩的：

```
Program received signal SIGSEGV
#0  fgets ()
#1  read_line ()
#2  test_read_line_1 ()
```

两处都要修：给 `read_line`/`load_board` 加空指针检查，以及让测试在正确的 cwd 下运行。

## 4. 默认分支重复初始化蛇 / Initializing snakes twice

```c
game = create_default_game();
game = initialize_snakes(game);   /* 错：覆盖 snakes 指针 */
```

`create_default_game` 已经建好 1 条蛇；`initialize_snakes` 会重新扫描棋盘、`malloc` 新数组、覆盖旧指针——第一次分配的内存永久泄漏。

## 5. 先移动后判死亡 / Checking death after moving

```c
update_head(game, i);
if (is_snake(next_square(game, i))) { /* 错：目标格已被覆盖 */ }
```

必须在移动前查询 `next_square`。移动后头已经占住目标格，原来的字符（墙/蛇身/食物）就查不到了。

## 6. 用 `fgets` 一次就认为读完整行 / Assuming one fgets call reads a line

`fgets(buf, n, fp)` 最多读 `n-1` 个字符。遇到长行会截断且**不报错**。判断读完整的唯一信号是末尾是 `\n`：

```c
if (line[len-1] == '\n') return line;   /* 完整 */
else { capacity *= 2; realloc... }      /* 继续读 */
```

## 7. `realloc` 后继续用旧指针 / Using the stale pointer after realloc

```c
realloc(line, capacity);          /* 错：返回值被丢弃 */
line[len] = 'x';                  /* 可能是已释放的内存 */
```

`realloc` 可能搬移内存块。必须 `line = realloc(line, cap)`。

## 8. 打印时补换行 / Adding a newline in print_board

```c
fprintf(fp, "%s\n", game->board[i]);   /* 错：行内已有 \n */
```

棋盘每行已经以 `\n` 结尾（`fgets` 保留、`create_default_game` 手动加）。再补一个就多出空行，21 组测试全部失败——而且 diff 输出会显示成“每一行之间多了空行”，容易误判成加载问题。

## 9. 假设所有行等长 / Assuming fixed row width

`13-sus-in.snk` 里有 20 列和 24 列混排。用 `char board[18][20]` 会越界写；用 `strlen` 也不安全（行尾有 `\n`，实际列数是 `strlen - 1`）。

正确做法是每行独立分配，需要列数时按 `'\0'` 或 `'\n'` 判断。

## 10. 把 `x` 排除在 `is_snake` 之外 / Excluding `x` from is_snake

死蛇的头是 `x`。如果 `is_snake` 不包含它，活蛇就能穿过死蛇的头部格子，死亡判定出现漏洞。

`is_head` 包含 `x`、`is_snake` 包含 `is_head`，两级都覆盖。

## 11. 用 `num_snakes` 之外的方式计数 / Counting snakes by heads

头可能是 `x`（死蛇），所以“数头”会漏掉死蛇。数尾 `wasd` 是可靠的，因为尾字符在死活蛇上都不变。

## 12. 忘记 `find_head` 的终止前提 / Assuming find_head always terminates

它依赖“蛇不自交”。非法棋盘（自交的环）会让循环永远转下去。题面不要求处理，但如果要写健壮版本，应该加步数上限：

```c
for (unsigned int steps = 0; steps <= game->num_rows * max_cols; steps++) { ... }
```

## 13. 忽略 `-Wextra` 的警告 / Ignoring conversion warnings

`get_next_row` 返回 `unsigned int`，`cur_row - 1` 在 `cur_row == 0` 时下溢成 `UINT_MAX`。棋盘有墙保护，实际不会走到，但 `-Wconversion` 会提醒这类隐式转换。官方 Makefile 就开了 `-Wconversion`。
