# 02 · 设计思路 / Design

## 内存形状 / Memory layout

```
game_t
├── num_rows      18
├── board         char** ──┬── "####################\n"
│                          ├── "#                  #\n"
│                          └── ...
├── num_snakes    1
└── snakes        snake_t* ── tail_row, tail_col, head_row, head_col, live
```

两个选择值得说明：

**行用 `char *` 而不是定长二维数组。** 因为棋盘允许不等长行（`13-sus-in.snk` 就有 20/24 列混排）。定长 `char board[18][20]` 遇到 24 列的行会写越界。

**蛇用数组而不是链表。** 蛇的数量在 `initialize_snakes` 时一次性确定（数棋盘上有几个尾字符），之后只读不改，数组是唯一合理的选择。

> **English:** Ragged rows force `char **`; the snake count is fixed at load time, so a flat array beats any linked structure.

## 每行都要有换行 / Every row keeps its newline

`print_board` 直接 `fprintf(fp, "%s", game->board[i])`，不做任何补字符。这意味着**换行必须存在行内**——`load_board` 读进来的行天然带 `\n`（`fgets` 保留它），`create_default_game` 则要手动 `strcat(row, "\n")`。

这个约定让“加载 → 打印”变成恒等变换，也是 21 组集成测试能逐字节比对的前提。

## 移动的四步 / Four steps per snake

```c
char next = next_square(game, i);          // 1. 看目标格

if (next == '#' || is_snake(next)) {       // 2. 判定死亡
    set_board_at(...head..., 'x');
    snake->live = false;
    continue;
}

update_head(game, i);                      // 3. 移动头

if (next == '*') add_food(game);           // 4a. 吃：不缩尾
else             update_tail(game, i);     // 4b. 不吃：缩尾
```

顺序不能换：

- 死亡判定必须在 `update_head` 之前（否则目标格已被覆盖）
- `update_head` 必须在 `update_tail` 之前，否则尾巴可能把新头的位置清掉（长度 1 的蛇会走到这里）
- `add_food` 必须在 `update_head` 之后，否则它可能把食物放到刚被头占据的格子上

## 长度 1 的蛇 / The one-cell snake

如果蛇只有一个格子（头就是尾），`update_head` 会把该格写成身体字符，然后 `update_tail` 读到的“当前尾”就是刚写的身体字符，接着把它清空并前移——结果正确，但过程依赖顺序。

这类退化情形是 `11-manyclose`、`12-corner` 两组测试重点覆盖的对象。

## `read_line` 的两次分配 / Two allocations in read_line

```c
unsigned int capacity = 32;
char *line = malloc(capacity);
while (fgets(line + length, capacity - length, fp)) {
    length += strlen(line + length);
    if (line[length-1] == '\n') return line;      // 完整一行
    capacity *= 2;                                 // 缓冲不够，翻倍
    line = realloc(line, capacity);
}
```

关键点：

- `fgets` 一次最多读 `size-1` 个字符并补 `\0`，所以**返回非 NULL 不代表读到换行**
- 判断“读完整行”的唯一可靠信号是最后一个字符是 `\n`
- `realloc` 之后指针可能变化，必须用返回值

10000 列的棋盘会触发约 9 次翻倍（32 → 8192 → 16384），总拷贝量 O(n)，均摊 O(1) 每字符。

## `find_head` 为什么能终止 / Why find_head terminates

从尾开始，沿当前字符的方向走一格，读新格子的字符，直到遇到 `is_head(c)` 为真。

终止性依赖一个棋盘不变量：**蛇是一条不自交的链**，且每个身体格的方向指向下一个更靠近头的格子。官方测试里的 `08-multisnake` 和 `13-sus` 都满足这个前提。

如果棋盘上有环（非法的自交蛇），这个循环会不终止。题面没有要求处理非法棋盘，所以不加防护——但 06 章会讨论如何加。

## 为什么 `next_square` 要单独存在 / Why a read-only probe

它是唯一“只看不改”的移动相关函数。把它抽出来有三个好处：

1. 死亡判定和移动决策共用同一次查询，避免重复计算
2. 单元测试可以直接断言它的返回值（4.2 的测试就是这么做的）
3. 让 `update_game` 的控制流读起来像规则本身
