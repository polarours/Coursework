# 07 · 延伸练习 / Extensions

## 1. 加一个自动寻路的 AI 蛇 / An AI snake

用 BFS 在棋盘上找一条到食物的最短路，避开蛇身。核心难点是**避免自陷**：贪心地追食物会让长蛇把自己围死。

一个可行的折中：先算到食物的最短路；走完之后用洪水填充检查剩余可达格数是否不小于蛇长；不满足就改走“追尾巴”的策略。

这个练习把 CS61C 的项目和 CS188 的搜索接在一起——本书 003/032 两题讲的正是这套搜索。

## 2. 用 `realloc` 之外的容器 / Replace the ragged array

把 `char **board` 换成一块连续内存 + 每行起始偏移：

```c
struct board {
  char *data;             /* rows * cols bytes, row-major */
  unsigned int *row_start;
  unsigned int num_rows;
};
```

好处是缓存局部性；代价是行不等长时要维护偏移表。可以写一个基准测试对比两种布局在 1000 步模拟下的耗时。

## 3. 双缓冲渲染 / Double buffering

现在的 `update_game` 原地修改棋盘。改成“读旧棋盘、写新棋盘”，可以让多蛇的移动真正并行（互不影响），也更容易做撤销/回放。

实现上要给 `game_t` 加一块 `next_board`，`update_game` 末尾交换指针。注意内存所有权会变复杂——`free_game` 要释放两块。

## 4. 记录与回放 / Record and replay

把每一帧的棋盘写成一个序列，就能做回放。格式可以复用现有 `.snk` 文本（帧之间用空行分隔），也可以换成二进制。

这一步会暴露一个设计问题：`deterministic_food` 依赖全局 `seed`，回放时必须一起保存。把 `seed` 移进 `game_t` 是更干净的做法——也顺带解决了“多个游戏实例互相干扰”的隐患。

## 5. 移植到 Rust / Port to Rust

用 `Vec<Vec<u8>>` 或 `Vec<u8>` + 行偏移表示棋盘，`&mut Game` 传递状态。对比点：

- 越界访问：C 是 UB，Rust 是 panic（`get`/`get_mut` 返回 `Option`）
- 所有权：`update_head` 需要同时改棋盘和结构体，Rust 的借用检查会强制你把这两个操作分开写
- 内存释放：`Drop` 自动完成 `free_game` 的工作

把 20 个函数逐个翻译过去，能非常直观地看到“C 里靠纪律维持的东西，Rust 里靠类型系统维持”。

## 6. 加一个最小的 GUI / Minimal GUI

用 `ncurses` 做终端渲染，或用 SDL2 画格子。这一步与算法无关，但会逼你处理“输入与游戏步进解耦”——现在的 `snake` 是一次性过滤器（读一次、走一步、退出），交互式版本需要一个事件循环。

`interactive_snake.c` 在 starter 里已经有雏形，可以作为起点。

## 7. 压力测试 / Stress test

生成 1000×1000 的棋盘、100 条蛇，测单步耗时与内存占用。这会暴露两个问题：

- `print_board` 用 `fprintf("%s")` 逐行写，大棋盘下 I/O 是瓶颈（可以改成 `fwrite` 整块）
- `initialize_snakes` 两遍扫描是 O(rows × cols)，棋盘大时值得合并成一遍

## 8. 与真实贪吃蛇的差距 / What the assignment simplifies

题目为了可测试做了几个简化，值得列出来：

- 没有“食物随机刷新在空位”的通用实现（`deterministic_food` 是确定性的，方便比对）
- 蛇不能穿墙（真实游戏常有环绕模式）
- 没有分数、没有加速、没有多食物
- 死蛇留在棋盘上，不消失

每一条都可以作为独立的小扩展，也正好说明“作业”与“产品”的差距往往在**规则完备性**而不是代码量。
