# 04 · 正确性与复杂度 / Correctness and complexity

## 不变量 / Invariants

游戏状态始终满足：

**I1.** 每条活蛇的棋盘字符构成一条不自交的链：尾字符 `wasd` → 若干 `^<v>` → 头字符 `WASD`，每个字符的方向指向链上下一个更靠近头的格子。

**I2.** `snake_t` 里的 `tail_row/tail_col` 与棋盘上的尾字符位置一致；`head_row/head_col` 与头字符位置一致。

**I3.** 死蛇（`live == false`）的头是 `x`，且之后不再被修改。

**I4.** 活蛇占用的格子数与它进入游戏时的长度一致；吃食物时 +1。

> **English:** The board and the structs must never disagree. Every helper updates both in the same call, and nothing outside `update_head`/`update_tail`/`update_game` touches either.

## 为什么 I1 能保持 / Why the chain stays valid

`update_head` 做的是“头往前挪一格”：旧头降级为身体字符（`head_to_body` 保证方向不变），新位置放原头字符。链的形状因此只是延长了一节，自交性由死亡判定保证——头只有在目标格**不是**蛇格时才会移动。

`update_tail` 做的是“尾巴往前跟一格”：旧尾清空，新的尾格由身体字符降级（`body_to_tail` 保持方向）。链缩短一节，其余不变。

两个操作都不改变中间部分的方向字符，所以 I1 在每一步后仍成立。

## 死亡判定的完备性 / Completeness of the death check

```c
if (next == '#' || is_snake(next))
```

`is_snake` 覆盖 `wasd^<v>WASDx`，即所有可能出现在蛇身上的字符。因此：

- 撞墙 → `#` → 死
- 撞自己（长度 ≥ 4 时可能）→ 自己的身体字符 → 死
- 撞别的蛇（头/身/尾）→ 蛇字符 → 死
- 撞死蛇的头 `x` → 死

`x` 被算进 `is_head` 是必要的：否则一条活蛇可以穿过死蛇的头部格子。

## 复杂度 / Complexity

| 操作 | 时间 | 空间 |
|---|---|---|
| `create_default_game` | O(rows × cols) | O(rows × cols) |
| `print_board` | O(rows × cols) | O(1) |
| `next_square` / `update_head` / `update_tail` | O(1) | O(1) |
| `update_game` | O(蛇数) | O(1) |
| `read_line` | O(行长) 均摊 | O(行长) |
| `load_board` | O(棋盘大小) | O(棋盘大小) |
| `find_head` | O(蛇长) | O(1) |
| `initialize_snakes` | O(rows × cols + 总蛇长) | O(蛇数) |

整个项目没有一处是 O(棋盘大小) 的单步操作——这是“棋盘即状态”设计的直接收益：移动一条蛇只需要读写常数个格子。

## 内存所有权 / Ownership

| 分配点 | 释放点 |
|---|---|
| `create_default_game`：`game`、`board`、每行、`snakes` | `free_game` |
| `load_board`：`board`、每行 | `free_game` |
| `initialize_snakes`：`snakes` | `free_game` |
| `read_line`：返回的 `line` | 调用方（`load_board` 存进 `board`，最终由 `free_game` 释放） |

唯一的泄漏风险是“调用 `initialize_snakes` 两次”——第二次会覆盖 `snakes` 指针。`main` 的默认分支因此**不**调用它（见 03 章 Task 7）。

## 边界表 / Boundaries

| 边界 | 期望 | 覆盖测试 |
|---|---|---|
| 长度 1 的蛇 | 头尾同一格，移动后仍正确 | `11-manyclose` |
| 蛇贴墙转弯 | 不越界 | `12-corner` |
| 多条蛇 | 各自独立移动，互撞则死 | `08-multisnake` |
| 不等长行 | 正确加载与打印 | `13-sus` |
| 棋盘填满蛇 | 无崩溃 | `10-filled` |
| 超大棋盘 | 正确加载 | `16-huge` ~ `21-bigL` |
| 10000 列 | `read_line` 多次翻倍 | 手工验证（本项目实测） |
| 不存在的输入文件 | `main` 返回 -1 | `run-nonexistent-input-file-test` |

## 与规格的一处张力 / A tension in the spec

规格 Task 1 只描述棋盘，单测却要求 `num_snakes == 1`。两种读法：

- 字面读法：`create_default_game` 只建棋盘，蛇由 `initialize_snakes` 建
- 单测读法：默认游戏必须是一个可立即推进的完整游戏

官方单测选了后者。这意味着 `create_default_game` 的输出与 `load_board + initialize_snakes` 的输出在结构上等价——这是更合理的设计，因为“默认游戏”本来就该能直接 `update_game`。

写这类作业时，**单测往往比文字规格更精确**。遇到冲突，以能同时满足两者的实现为准。
