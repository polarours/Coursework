## 第二层：官方单元测试

```bash
cc -std=c99 -Wall -O2 -o unit-tests unit_tests.c snake_utils.c asserts.c
```

注意**不要**加 `game.c`——`unit_tests.c` 第 8 行是 `#include "game.c"`，因为它要直接调用 `static` 的 helper。

这是本项目第一个真实的编译问题：

```
multiple definition of `create_default_game'
```

链接器把 `game.c` 编了两次（一次显式、一次被 include）。去掉命令行里的 `game.c` 即可。

第二个问题更隐蔽：单测用相对路径读棋盘。

```c
FILE *fp = fopen("tests/01-simple-in.snk", "r");
```

所以必须在**含 `tests/` 子目录**的目录下运行。`tests/run.sh` 的做法是在 `tests/.build/` 里建一个指向 `upstream/tests` 的软链接，然后 `cd` 进去运行：

```bash
ln -sfn "$(cd upstream/tests && pwd)" "$BUILD/tests"
(cd "$BUILD" && ./unit-tests)
```

## 官方单测抓到的规格误读 / What the unit tests corrected

第一次跑单测，第一个用例就失败：

```
Testing create_default_game (Task 1)...
Assertion error: expected number of snakes to be 1 but got 0
```

我按规格字面只建了棋盘（`num_snakes = 0`），认为蛇该由 `initialize_snakes` 建。单测要求默认游戏**自带**那条蛇。

修正后 `main` 的默认分支也要跟着改——不能再调用 `initialize_snakes`，否则会覆盖并泄漏已经建好的 `snakes` 数组。

这个教训比代码本身重要：**规格文字与单测冲突时，单测通常是更精确的那一方**，因为它就是评分器。

## 手工验证的四条 / Four manual checks

集成测试只覆盖“从文件读”，剩下三条路径要手动验：

```bash
# 1. 默认棋盘
./snake | head -3
# ####################
# #                  #
# #  d>D   *         #     ← 蛇整体右移一格

# 2. 标准输入
./snake --stdin < tests/01-simple-in.snk | sed -n 3p
# #  d>D   *         #

# 3. 不存在的文件
./snake -i nope.snk; echo $?
# 255                        ← -1 作为退出码

# 4. 超长行（10000 列）
./snake -i long.snk -o out.snk && wc -c out.snk
# 30005
```

第 4 条专门打 `read_line` 的 `realloc` 路径：32 字节起步，翻倍到 16384，中途约 9 次重新分配。

## 内存检查 / Memory checks

官方 Makefile 提供：

```bash
make valgrind-test-free-game
```

如果本机没有 Valgrind，可以用编译器的检查器代替：

```bash
cc -fsanitize=address,undefined -g -o snake-asan snake.c game.c snake_utils.c
./snake-asan -i tests/09-everything-in.snk -o /dev/null
```

本项目在 21 组测试上跑 ASan 无报告（`free_game` 之后无泄漏，`read_line` 的 `realloc` 路径无越界）。

## 调试手段 / Debugging tools

规格推荐 `cgdb` + `p print_board(game, stdout)`。这个技巧很实用：断在 `update_game` 内部时，一条命令就能把整个棋盘打出来，比逐个 `p game->board[i]` 快得多。

在纯终端环境里，等价的低成本做法是在 `update_game` 开头加一行：

```c
if (getenv("SNEK_DEBUG")) print_board(game, stderr);
```

棋盘走 stderr，正常输出不受影响，`diff` 也不会被打乱。
