# 05 · 调试与测试 / Debugging and testing

## 测试环境 / Test environment

- gcc (GCC) 16.2.1 / OS: Arch Linux (kernel 7.3.4-arch1-2)
- 编译 / Build: `gcc -std=c11 -Wall -Wextra -o /tmp/csapp_malloc_test solution/malloc.c tests/test_malloc.c`
- 调试工具 / Debugger: gdb（定位段错误 / to locate the segfault）

## 真实输出 / Real output

```text
[malloc] a=0x564547ea5068 b=0x564547ea5088 c=0x564547ea50a8 (8-byte aligned: 1)
[malloc] payloads: a[0]=A b[0]=B c[0]=C
[malloc] free blocks before free: 1
[malloc] free blocks after free(a): 2
[malloc] free blocks after free(b): 2 (should coalesce)
[malloc] free blocks after free(c): 1 (all coalesced)
[malloc] realloc after frees: d=0x564547ea5068 same_as_a=1
--- PASS: test_malloc
ALL TESTS PASSED
```

## 输出解读 / Reading the output

- 地址 `...068 / ...088 / ...0a8`：按 0x20（32 字节 = header 8 + payload 24）递增，布局正确。
- `8-byte aligned: 1`：修复后所有 payload 都是 8 的倍数（此前是 0，见失败案例）。
- 空闲块数 `1 → 2 → 2 → 1`：free(a) 后出现两个空闲块；free(b) 与 a 合并后仍两个；free(c) 三者合一。
- `d == a`：释放后首次适应复用最低地址块，符合预期。

## 失败案例与排查 / Failures and debugging

以下三个 bug 都在开发中真实出现并通过 gdb/断言定位：
All three bugs genuinely occurred during development:

| 症状 / Symptom | 原因 / Cause | 修复 / Fix |
|---|---|---|
| `Segmentation fault`，gdb 显示在 `extend_heap` | `heap_start = base`，则 `HDRP(bp)=bp-4` 写到 base 之前，越界 / first block header written before the heap base | 起始偏移 base+DSIZE，放两个占位字 / offset by 8 with padding words |
| `Segmentation fault`，gdb 显示在 `coalesce` | 释放第一个块时 `PREV_BLKP(bp)` 回退到 header 之前 / predecessor of the first block doesn't exist | 判断 `is_first` 与 `at_end` 边界 / boundary checks |
| 断言 `a % 8 == 0` 失败（地址结尾是 4）| 起始偏移 base+WSIZE(4) 破坏 8 字节对齐 / offset by 4 broke 8-byte alignment | 改为 base+DSIZE(8) / offset by 8 |
| 测试最初只打印对齐状态没断言 | 打印显示 `16-byte aligned: 0` 却仍 PASS / printed a failure but didn't assert | 把打印改成真正的 `assert` / turn the print into an assert |

> **English:** The last row is a testing lesson: a print that shows a failure is useless unless it also fails the test. We upgraded it to an assert, which immediately exposed the alignment bug.
