# 02 · 设计思路 / Design

## 一切搜索器 = 同一骨架 + 不同队列 / One skeleton, different queues

DFS/BFS/UCS/A* 的唯一区别是 frontier 的弹出策略（LIFO / FIFO / g / g+h）。参考实现抽 `_graph_search(problem, heuristic, mode)`，四个公开函数各传一个 mode——**算法差异被压缩成一行参数**，这正是 CS188 "搜索 = 队列策略"的教学主旨。

> **English:** All four solvers share one graph-search skeleton; the mode string is the only difference — the assignment's whole point is that search algorithms are queue policies.

## 三种去重时机 / Three deduplication points

- **DFS**：弹出后检查 visited 再展开 / dedupe at expansion
- **BFS**：入队时去重（同层重复入队会爆内存）/ dedupe at enqueue
- **UCS/A***：`best_g` 字典 + 惰性删除（弹出的过期条目直接跳过）/ lazy deletion

三个时机各有理由，搞混就是 05 章的 BFS 大坑。

## Corners 状态：位置 × 访问标记

状态 = `(position, visited_corners 四元组)`。**为什么必须带标记**：光记位置无法区分"到过左上角"与"没到过"——搜索会无限退化。标记用不可变 tuple（可哈希、入 set）。

## 启发式：max 而非 min / max, not min

`corners_h = 到最远未访问角的曼哈顿距离`、`food_h = 到最远剩余食物的曼哈顿距离`。可采纳性论证（04 章详述）：完成路径必须经过**每一个**未访问目标，故路径长 ≥ 每个目标的直达距离 → ≥ max。

> **English:** Admissibility by domination: any completing path must reach every remaining target, so its length bounds each direct distance — and therefore their max.
