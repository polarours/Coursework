# 06 · 踩坑清单 / Pitfalls

## 1. BFS 双重去重（本作业开发中的真实 bug）/ Double dedup, the real bug

- 症状：maze-tiny 上 DFS/UCS 都 Win，**BFS 独家 Loss**，日志 `SolutionNotFoundError`。
- 原因：pop 侧与入队侧共用同一个 `visited`——入队时已标记的节点弹出时又被 `continue` 跳过，**除起点外一个节点都没展开**。
- 修复：BFS 弹出侧不检查（入队时已去重）；DFS 保留弹出时检查。两算法的去重时机本来就不同，写成同一个分支是错的。
  *BFS dedupes at enqueue, DFS at expansion; sharing one visited-check branch silently expands nothing.*

## 2. `Position(row, col)` 参数顺序 / the (row, col) order

- 第一版四角写成了 `Position(w-2, 1)`（当成 (x, y)）——NE/SW 全错。pacai 的 Position 构造是 **(row, col)**。类型检查器（Pyright）也抓出了 tuple 标注不匹配——**先跑静态检查再跑游戏**。

## 3. board 误配 / the board↔problem mismatch

- 见 05 章：search-* 板 + position 搜索 = 游戏永不结束。选对 board 是本地验证的前提，官方 autograder 用哪块板考什么能力是有设计意图的。

## 4. SimpleComparable 的 JSON 比较 / JSON-based equality is slow

- `SearchNode` 基类的 `__eq__/__hash__` 走 JSON 序列化（`edq.util.json.dumps`）——corners 展开数十万次时每步都序列化。CornersSearchNode 手写 `__eq__/__hash__`（位置 + 标记元组），85 万节点 5 秒可跑完。

## 5. submodule pin tag 的写法 / pinning a tag

- `git submodule add -b v2.1.0` 失败（`-b` 只接受分支）；正解：正常 add 后 `git fetch --depth 1 origin tag v2.1.0 && git checkout v2.1.0`，gitlink 记 commit，README 注明 pin 的版本。
