# 02 · 设计思路 / Design

## 一切从"测试是合同"出发 / The tests are the contract

官方测试文件覆盖了 17 个函数的正反两面，所以设计的顺序是：**先读测试，再写实现**。逐条把测试断言翻译成需求清单（如 `EXPECT_THROW(random(..., 5, 2), std::logic_error)` → "min>max 必须抛 logic_error 而不是交换参数"），再按清单落码。

> **English:** Translate each assertion into a requirement before writing a single line; the suite doubles as the statement of work.

## 三层结构 / Three layers

1. **形状检查层 / shape guards**：维度不匹配、空矩阵，先判后动
2. **纯计算层 / pure computation**：转置、数乘等直写
3. **递归家族 / recursive family**：`minor(n, m)` 去掉第 n 行 m 列 → `determinant` 按第一行余子式展开 → `inverse` 用伴随矩阵 / det

## 关键语义决策 / Key semantic decisions

- **空积约定**：`determinant({}) = 1.0`（恒等元的空积），与 MATLAB 一致
- **ero_sum 方向**：`ero_sum(a, r1, c, r2)` = row_r2 += c × row_r1——受影响的是**第二个**行参数
- **upper_triangular 不选主元**：遇到首主元为 0 时，用"把下方足够大的行加到首行"的方式绕开，而不是 swap
