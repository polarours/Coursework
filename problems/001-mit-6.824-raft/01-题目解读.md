## 需求概述 / Requirements

Raft 是一个用来管理**复制日志**的共识算法。我们要在一组可能宕机、网络可能分区的服务器上，让所有节点对「日志里有哪些命令、顺序如何」达成一致。

Raft is a consensus algorithm for managing a **replicated log**. The goal: a cluster of servers that may crash or be partitioned must all agree on which commands exist in the log and in what order.

整个问题可拆成四个子问题 / The problem decomposes into four subproblems:

1. **Leader 选举 / Leader election**：任意时刻最多一个 leader；没有 leader 时能在有限时间内选出一个。
   *At most one leader at any time; when none exists, one must be elected within a bounded time.*
2. **日志复制 / Log replication**：leader 接收客户端命令，复制到多数派节点，然后提交并通知上层状态机。
   *The leader accepts commands, replicates them to a majority, commits them, and notifies the state machine.*
3. **安全性 / Safety**：已提交的条目不能丢失或被覆盖；不同节点的已提交日志必须一致（状态机安全）。
   *Committed entries are never lost or overwritten; committed logs must be identical across nodes.*
4. **持久化 / Persistence**：节点重启后能恢复 term、投票记录和日志。
   *After a restart, a node can recover its term, vote, and log.*

> **English:** The key insight of Raft is *strong leadership*: only the leader accepts client requests. This decomposes consensus into election, replication, and safety — the design choice that makes Raft more teachable than Paxos.

## 输入与输出 / Input and output

- 上层调用 `Start(command)` 提交一条命令；返回日志 index 和是否成功（非 leader 返回 false）。
  *The application calls `Start(command)`; it returns a log index and a success flag (false if not leader).*
- 已提交的命令通过 `applyCh` 通道投递给上层状态机，携带 index 和 command。
  *Committed commands are delivered on `applyCh` with their index and command.*

## 边界条件 / Edge cases

- 偶数节点可能平分选票 → 需要随机化选举超时打破僵局。
  *Even-sized clusters can split votes → randomized election timeouts break the tie.*
- 网络分区后，少数派分区里的旧 leader 必须停止提交。
  *After a partition, an old leader in the minority must stop committing.*
- 新 leader 的日志可能落后于某些 follower → 需要通过 `nextIndex` 回退补齐。
  *A newly elected leader may have a stale log relative to some followers → `nextIndex` backtracking repairs it.*
- 日志冲突（同一 index 上 term 不同）→ 必须截断冲突条目及其后所有条目。
  *Conflicting entries (same index, different term) must be truncated along with everything after them.*

## 明确不做 / Non-goals

- 不实现日志压缩 / snapshot（属于进阶实验，见 07 延伸练习）。*No log compaction/snapshot (an advanced exercise in chapter 07).*
- 不实现成员变更 / membership reconfiguration。
- 不实现真实的 TCP/RPC 传输；我们用内存网络模拟，可注入宕机和分区。
  *No real TCP/RPC transport; we use an in-memory network that can inject crashes and partitions.*

## 验收标准 / Acceptance criteria

- [x] 唯一 leader 选出（TestElection）/ exactly one leader elected
- [x] 3 条命令复制到全部 3 个节点并按序 apply（TestLogReplication）
- [x] leader 宕机后新 leader 选出并继续复制（TestLeaderFailover）
- [x] 分区时少数派不提交、多数派提交、恢复后日志收敛（TestPartitionSafety）
- [x] `go test -race` 无数据竞争 / no data races
