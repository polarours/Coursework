# 04 · 正确性与复杂度 / Correctness and complexity

## 不变量 / Invariants

以下不变量贯穿整个实现 / These invariants hold throughout:

1. **选举安全 / Election safety**：一个 term 内最多一个 leader。
   *At most one leader can be elected in a given term.*
2. **Leader 只追加 / Leader append-only**：leader 从不覆盖自己的日志条目。
   *A leader never overwrites its own log entries.*
3. **日志匹配 / Log matching**：两个日志中相同 index 且相同 term 的条目，其前面所有条目都相同。
   *If two logs contain an entry with the same index and term, all preceding entries are identical.*
4. **Leader 完备 / Leader completeness**：某条目在某 term 被提交，则该条目会出现在所有更高 term 的 leader 日志中。
   *If an entry is committed in a term, it appears in the log of every higher-term leader.*
5. **状态机安全 / State machine safety**：若某 index 上已 apply 一条命令，则其他节点在同一 index 不会 apply 不同命令。
   *If a command is applied at an index, no other node applies a different command at that index.*

> **English:** Invariants 1–2 come from the voting rule (one vote per term + up-to-date check). Invariants 3–5 are enforced by log matching, the commit rule, and the request-vote log comparison.

## 证明思路 / Proof sketch

**为什么少数派不能提交？/ Why can't the minority commit?**

提交需要多数派（3/5 节点中的 3 个）确认 `matchIndex >= n`。网络分区后，旧 leader 所在小分区只有 2 个节点，`count` 最多 2 < 3，因此 `commitIndex` 无法推进。

Commit requires a majority (`matchIndex >= n` from 3 of 5 nodes). After a partition, the old leader's group has only 2 nodes, so `count` ≤ 2 < 3 and `commitIndex` cannot advance.

实测证据 / Measured evidence:

```text
[TestPartitionSafety] 少数派 leader Start=true index=1 commitIndex=0
```

命令被接收（写进本地日志），但**没有提交**——这正是需要区分的两件事。
The command was accepted into the local log but **not committed** — an important distinction.

**为什么提交规则要检查 term？/ Why check the term in the commit rule?**

若 leader 提交了一个旧 term 的条目，随后新 leader 可能缺少该条目，违反 Leader 完备性。Raft 论文 Figure 8 给出了反例。我们的实现只在 `log[n].Term == currentTerm` 时提交。

Committing an old-term entry can violate leader completeness (Raft Figure 8). We only commit when `log[n].Term == currentTerm`.

## 复杂度 / Complexity

设日志长度 L，集群节点数 N / Let L be log length, N the cluster size:

| 操作 / Operation | 时间 / Time | 空间 / Space |
|---|---|---|
| 选举一次 / One election | O(N) 次 RPC（并行）/ O(N) RPCs in parallel | O(N) |
| 提交一条命令 / Commit one command | O(N + L)（回退时最坏 O(L) 次 RPC）/ O(N + L) worst case | O(N) |
| 心跳一次 / One heartbeat | O(N) | O(N) |
| 单节点日志存储 / Per-node log | — | O(L) |

> **English:** The O(L) worst case comes from `nextIndex--` backtracking one entry at a time. Chapter 07 asks the reader to optimize this using conflict hints (return the conflicting term and jump to the last index of that term).
