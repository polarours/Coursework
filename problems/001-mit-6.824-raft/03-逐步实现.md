# 03 · 逐步实现 / Step-by-step implementation

每个阶段都留下可验证的中间产物 / Each stage leaves a verifiable artifact.

## 阶段 1 / Stage 1 — 数据结构与网络骨架

先定义日志、RPC 消息和内存网络。网络层要能模拟宕机（丢弃 RPC）和分区（不同组之间不通）。

First define logs, RPC messages, and an in-memory network that can simulate crashes (drop RPCs) and partitions (isolated groups).

```go
type LogEntry struct {
    Term    int
    Command string
}

type RequestVoteArgs struct {
    Term, CandidateId, LastLogIndex, LastLogTerm int
}
```

验证 / Verify: `go build ./...` 通过 / builds successfully.

> **English:** Building the network abstraction first pays off: every later test can inject failures without touching protocol code.

## 阶段 2 / Stage 2 — Leader 选举

自增 term、投给自己、并行发 RequestVote；拿到多数派票后成为 leader。

Increment term, vote for self, fan out RequestVote RPCs in parallel; become leader on a majority.

```go
rf.currentTerm++
rf.state = Candidate
rf.votedFor = rf.id
votes := 1  // 自己 / self
majority := (len(rf.peers)+1)/2 + 1
```

投票请求的两大条件 / Two conditions for granting a vote:

1. `args.Term >= rf.currentTerm`（旧 term 的请求直接拒绝）/ reject stale terms.
2. 候选人的日志**至少和自己一样新**（lastLogTerm 更大，或相同且 index 更大）。
   *The candidate's log is at least as up-to-date as ours.*

验证 / Verify: 运行 `TestElection`，应看到唯一 leader。
Run `TestElection`; expect exactly one leader.

## 阶段 3 / Stage 3 — 日志复制与提交

leader 通过 AppendEntries 发送条目；follower 做一致性检查（prevLogIndex/prevLogTerm 必须匹配），冲突时截断。

The leader sends entries via AppendEntries; the follower checks log matching (prevLogIndex/prevLogTerm must match) and truncates on conflict.

```go
if args.PrevLogIndex >= len(rf.log) ||
   rf.log[args.PrevLogIndex].Term != args.PrevLogTerm {
    return  // Success 默认 false → leader 回退 nextIndex
}
```

提交规则 / Commit rule:

```go
if count >= len(rf.matchIndex)/2+1 && rf.log[n].Term == rf.currentTerm {
    rf.commitIndex = n
}
```

验证 / Verify: `TestLogReplication` 中 3 个节点 apply 出完全相同的 `[SET a=1 SET b=2 DEL a]`。

## 阶段 4 / Stage 4 — 故障与分区

leader 宕机后，follower 因收不到心跳而超时选举；分区时少数派 leader 的 AppendEntries 全被网络丢弃，无法推进 commitIndex。

When the leader crashes, followers time out and elect; under a partition, the minority leader's AppendEntries are all dropped, so its commitIndex cannot advance.

验证 / Verify: `TestLeaderFailover` 与 `TestPartitionSafety`。
In `TestPartitionSafety`, the minority leader accepted `minority-write` at index 1 but `commitIndex` stayed at 0 — a direct demonstration of safety.

## 阶段 5 / Stage 5 — 应用层投递与持久化

`applyLoop()` 把已提交条目送给状态机；`save()` 在 term/vote/log 变化时写回 persister。

`applyLoop()` delivers committed entries; `save()` persists term/vote/log on every change.

验证 / Verify: `go test -race ./...` 通过，无数据竞争。
