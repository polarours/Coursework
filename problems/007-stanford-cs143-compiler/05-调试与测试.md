## 输出解读 / Reading the output

- 指令序列 `LOAD x, LOAD x, BINOP *, LOAD y, LOAD y, BINOP *, BINOP +` 正是 `x*x + y*y` 的后缀式（逆波兰）——栈式虚拟机的典型代码形状。
- 输出 `[25, 0, 1, 2, 1]`：25=3²+4²（勾股定理），0/1/2 来自 while 循环，最后的 1 来自 `if (x<y)` 为真。
- 阶乘 `[120]` 证明 while 循环与乘法在生成的指令下正确工作。

## 失败案例与排查 / Failures and debugging

开发中真实遇到的三个 bug：
Three bugs genuinely encountered:

| 症状 / Symptom | 原因 / Cause | 修复 / Fix |
|---|---|---|
| `SyntaxError: 未知语句 Token(;,';')` | 解析器没有消费语句末尾的分号 / statement terminator not consumed | 在 `block()` 中统一 `eat(';')` |
| `期望 )，实际 <` | 单字符 `<` 被词法器归为 `<` 类型，而 `compare()` 只认 OP 类型 / single-char `<` tokenized as its own type | 单字符 `<`/`>` 归入 OP |
| `期望 =，实际 OP` / 随后 `未知字符 '='` | 把 `=` 误归入 OP，后又从 OP 分支排除却忘了加回普通分支 / `=` classification bounced between branches | 双字符 `==`→OP，单字符 `=`→赋值类型 |

> **English:** All three bugs are in the lexer/parser boundary — the most error-prone part of a hand-written front end. The tokenizer must produce exactly the token types the parser expects.
