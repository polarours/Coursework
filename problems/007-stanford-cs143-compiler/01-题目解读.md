## 需求概述 / Requirements

Stanford CS143 的编译器课程让学生用 COOL 语言实现一个完整编译器。本项目实现一个迷你编译器，覆盖编译器的经典流水线：

Stanford CS143 builds a full compiler for the COOL language. Our mini-compiler covers the classic pipeline:

1. **词法分析 / Lexing**：字符流 → token 流（关键字、标识符、数字、运算符）。
2. **语法分析 / Parsing**：token 流 → 抽象语法树（AST），用递归下降法。
   *Token stream → abstract syntax tree via recursive descent.*
3. **代码生成 / Code generation**：AST → 栈式虚拟机指令（PUSH/LOAD/STORE/BINOP/JZ/JMP/PRINT）。
4. **执行 / Execution**：虚拟机解释指令，得到程序输出。

> **English:** CS143 is a capstone that ties together automata theory, data structures, and systems. Our mini version keeps the full front-end→back-end pipeline so students see how each phase connects.

## 输入与输出 / Input and output

- 输入：源程序字符串（支持 let 赋值、算术、比较、if/else、while、print）。
  *Input: source text with assignment, arithmetic, comparison, if/else, while, print.*
- 输出：token 序列、指令序列、程序运行结果（print 输出列表）、最终变量环境。
  *Output: tokens, instructions, program output, final environment.*

## 边界条件 / Edge cases

- 分号是语句结束符，必须在解析中消费 / Semicolons terminate statements and must be consumed.
- 单字符比较符（`<`、`>`）与双字符（`<=`、`>=`、`==`、`!=`）要归类一致。
  *Single and double-character comparison operators must be tokenized consistently.*
- `=` 是赋值，不是比较；`==` 才是比较。
  *`=` is assignment; `==` is comparison.*
- if/while 的跳转目标要在生成时回填（backpatching）。
  *Jump targets for if/while must be backpatched during generation.*

## 明确不做 / Non-goals

- 不实现类型检查、优化、寄存器分配或真实机器码 / No type checking, optimization, register allocation, or machine code.
- 不使用 COOL 语言；用自设计的迷你语言（语法更简单）。
  *No COOL; a simpler custom language.*
