# 02 · 设计思路 / Design rationale

## 整体架构 / Architecture

```text
源代码字符串
   │ lex()
   ▼
Token 流 ──────► Parser（递归下降）──────► AST
                                            │ compile_ast()
                                            ▼
                                    栈式虚拟机指令
                                    PUSH/LOAD/STORE/BINOP/JZ/JMP/PRINT
                                            │ execute()
                                            ▼
                                     print 输出 + 变量环境
```

> **English:** The phase separation is the single most important architectural idea in compilers: each phase has a clean interface (string → tokens → AST → instructions), so you can test each one independently and swap implementations.

## 关键决策 / Key decisions

| 决策 / Decision | 选择 / Choice | 理由 / Why |
|---|---|---|
| 词法 / Lexing | 手写扫描器 | 简单语言足够；教学上比自动生成更透明 / transparent for teaching |
| 语法 / Parsing | 递归下降 + 优先级爬升 | 与 CS143 讲的 LL 分析一致 / matches LL parsing taught in CS143 |
| 中间表示 / IR | AST（dataclass）| 结构化、易遍历 / structured and easy to walk |
| 目标 / Target | 栈式虚拟机 | 无需真实机器码，指令直观 / no machine code needed; instructions are intuitive |
| 跳转回填 / Backpatch | 先放占位 JZ(None)，生成完再填 | 单遍生成控制流指令的标准技巧 / standard single-pass control-flow generation |
| 运算符 / Operators | 比较符统一为 OP token | 避免 `<` 与 `<=` 归类不一致（真实踩坑）/ avoid inconsistent tokenization |

## 备选方案 / Alternatives

- **生成 x86 汇编**：更真实但依赖汇编器与 ABI；栈式 VM 让输出可直接运行验证。
  *Real assembly needs toolchains; a stack VM gives directly runnable output.*
- **用 yacc/ANTLR 自动生成 parser**：工业做法，但隐藏了原理；手写递归下降更教学。
  *Generators hide the mechanics; hand-written descent teaches them.*

> **English:** Backpatching is worth studying closely: when generating `if`, you don't know the jump target until you've generated the body. Placing a placeholder and filling it later is the key trick.
