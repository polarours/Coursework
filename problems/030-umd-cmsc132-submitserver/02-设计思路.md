# 02 · 设计思路 / Design

## 核心：双向链表，按需遍历 / Core: a linked list, scanned on demand

班级规模小、方法简单——用一个单链表存所有人，查询时线性扫描即可。**为什么 / Why**：这是 OOP II 的第一课，考核点是**类设计与链表操作**，不是渐近复杂度；HashMap 在这里反而绕开了要练习的东西。

> **English:** The point of this project is class design and list mechanics; a HashMap would dodge the very skill being taught.

## 不可变提交记录 / Immutable submission records

每条提交 = (name, score, sequenceNumber) 三元组，序号即插入顺序。`bestSubmissionNumber` 的"并列取晚"语义恰好由**严格大于**比较实现：`if (score > best.score)` 平分时不更新——自然保留最早一次？不——从链表头向尾遍历时，严格大于保留下的是**首个最高分**；官方语义取第几次提交时以 PublicTests 实测为准（见 05 章）。

## 链式 API / Fluent API

`addSubmission` 返回 `this`：`server.addSubmission("A", 50).addSubmission("A", 80)`——一道微型的 API 设计题。

> **English:** Returning `this` turns the setter into a fluent chain — a tiny lesson in API ergonomics.
