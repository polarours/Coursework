## 需求概述 / Requirements

UMD CMSC132 的 Project 1：实现一个作业提交服务器 `SubmitServer`——"作业管理系统"的最小内核。给定课程映射（学生 → 一组分数），支撑以下查询：

UMD CMSC132 Project 1: implement `SubmitServer`, the minimal kernel of an assignment-management system, supporting queries over a student → scores mapping:

1. `numSubmissions()` / `numSubmissions(name)`：总提交数 / 某人提交数
2. `bestSubmissionScore(name)`：某人最高分
3. `bestSubmissionNumber(name)`：最高分是第几次提交（1-based）
4. `satisfactory(name)`：最高分是否达标
5. `addSubmission(name, score)`：链式风格追加一条提交
6. 提交记录不可变，分数合法范围 [0, 100]

**这道题最特别的地方**：官方不发布文字题面，**PublicTests.java 就是规格**——15 个 JUnit 测试精确地定义了每个方法的行为。UMD 的传统即"测试即规格 / tests as spec"。

> **English:** UMD defines the contract not in prose but in PublicTests.java: 15 JUnit tests that pin down every method's observable behavior. Reading tests as requirements is itself the trained skill.

## 边界条件 / Edge cases（官方测试未覆盖、我们实测补齐）

- `numSubmissions(null)` → upstream 实现返回 -1 / returns -1 (verified empirically)
- 非法分数（>100 或 <0）→ 静默忽略 / invalid scores silently ignored
- 同一人多次提交、并列最高分 → bestSubmissionNumber 取**最晚**一次 / ties resolve to the latest
- 空服务器上一切查询应安全 / all queries safe on an empty server
