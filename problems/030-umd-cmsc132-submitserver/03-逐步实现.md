# 03 · 逐步实现 / Step-by-step implementation

> 本题 upstream 已含一份学生实现；本仓库的角色是**验证 + 边界语义考据**（解法结构按 upstream 对照描述，另见 05 章对官方测试的逐条核实）。
> *Upstream already carries a student implementation; our role is verification plus boundary semantics archaeology.*

## 结构

```
SubmitServer
 ├── 链表节点：name → List<Submission>（每人一组提交）
 └── 方法：numSubmissions / bestSubmissionScore / bestSubmissionNumber /
          satisfactory / addSubmission(name, score) → this
```

## 关键方法

- `bestSubmissionScore(name)`：遍历该生提交列表，`max` 归约
- `bestSubmissionNumber(name)`：同一遍历里记录达到 max 的序号
- `addSubmission`：非法分数直接丢弃（upstream 实测行为），合法则追加并返回 `this`
- `satisfactory(name)`：`bestSubmissionScore(name) >= threshold`

## 对照实验设计 / Verification design

1. 编译 upstream 实现 + 官方 PublicTests → 全绿确认其可用作参考
2. 自写 EdgeTests 追问官方未定义的分支（null、非法分数、空表）
3. 把实测行为记录进 README——**不确定的语义以代码为准，不臆造**
   *Empirically observed semantics, not invented ones.*
