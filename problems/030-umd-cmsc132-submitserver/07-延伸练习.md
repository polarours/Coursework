# 07 · 延伸练习 / Extensions

## 1. 换 HashMap / Switch to a HashMap

把人 → 提交列表的容器换成 `HashMap<String, List<Submission>>`，重跑官方测试。哪些复杂度改变了？哪些行为必须小心保留（链表遍历顺序敏感的语义）？

## 2. 并列最高分 / Tied best scores

官方测试不覆盖"两次提交同分"时 `bestSubmissionNumber` 的取值。写测试锁定一种语义（最早 or 最晚），并给出你的理由——这正是"测试即规格"课程想教的：**没写的规格，你要自己定**。
*Undefined by the tests? Then you define it — and defend it.*

## 3. 流式统计 / Streaming statistics

不存历史提交，只维护 (count, bestScore, bestNumber, satisfactory)：`addSubmission` O(1) 更新。空间从 O(提交数) 降到 O(人数)——什么时候这种压缩不可接受？（提示：`bestSubmissionNumber` 之外若再要 median 呢）

## 4. 防御式 API / Defensive API

把 null / 非法分数从"静默忽略"改为抛 `IllegalArgumentException`，官方测试会挂几条？讨论两种设计的取舍（宽容 vs 严格）。
