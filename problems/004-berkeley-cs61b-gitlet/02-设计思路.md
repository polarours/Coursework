# 02 · 设计思路 / Design rationale

## 整体架构 / Architecture

```text
 工作区 (hello.txt) ──add──▶ 暂存区 (stage: 文件名→blob hash)
                                  │
                             commit（拍快照）
                                  ▼
 .gitlet/objects/  ◀── 提交树 (tree: 文件名→blob hash)
   ├── <blob hash>       │
   └── <commit hash>     └── parent → 上一个提交 → ... → initial commit
```

> **English:** The key abstraction is that a commit is an immutable snapshot: it stores the *entire* file tree (as a mapping to blob hashes), not a diff. Diffs are computed on demand by comparing two snapshots.

## 关键决策 / Key decisions

| 决策 / Decision | 选择 / Choice | 理由 / Why |
|---|---|---|
| 对象命名 / Object naming | SHA-1 内容哈希 | 内容变则哈希变，天然去重 / content changes change the hash, giving deduplication for free |
| 提交内容 / Commit payload | 整棵树快照（文件名→blob hash）| 简化实现；diff 可后续计算 / snapshot simplifies; diff can be computed later |
| 历史结构 / History | 线性父链 | 教学版不需要合并 / no merge needed for teaching |
| 持久化 / Persistence | pickle 序列化对象 | 简单；真实 Git 用 zlib + 自定义格式 / simple; real Git uses zlib + custom format |
| uid 一致性 / uid consistency | uid 由 `_serialize()` 的哈希决定 | 开发中踩过的坑：两处哈希不一致导致读不回来 / real bug we hit and fixed |

## 备选方案 / Alternatives

- **存 diff 而非快照**：省空间，但实现 checkout 复杂；教学版先掌握快照。
  *Storing diffs saves space but complicates checkout; snapshots first.*
- **用 SQLite 存元数据**：更工程化，但引入依赖；pickle 让实现自包含。
  *SQLite is more engineering but adds a dependency; pickle keeps it standalone.*

> **English:** The `uid == hash(serialize())` invariant is the single most important rule in content-addressable storage. Violating it produced a `FileNotFoundError` in our real test run.
