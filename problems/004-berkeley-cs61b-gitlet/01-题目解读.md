## 需求概述 / Requirements

Gitlet 是 CS61B 的招牌项目：从零实现一个简化版 Git。核心是把"版本控制"还原成几个基本机制：

Gitlet is CS61B's signature project: build a simplified Git from scratch. Version control reduces to a few mechanisms:

1. **内容寻址存储 / Content-addressable storage**：文件与提交用其内容的 SHA-1 哈希命名，相同内容只存一份。
   *Files and commits are named by SHA-1 of their content; identical content is stored once.*
2. **提交图 / Commit graph**：每次提交指向父提交，形成一条链（简化版只有线性历史）。
   *Each commit points to its parent, forming a chain (linear history in our simplified version).*
3. **暂存区 / Staging area**：`add` 把工作区文件放入暂存区，`commit` 把暂存区内容固化成新提交。
   *`add` stages files; `commit` freezes the staged content into a new commit.*
4. **命令 / Commands**：init、add、commit、log、status、checkout。
   *Commands: init, add, commit, log, status, checkout.*

> **English:** Gitlet is deceptively hard: the concepts are simple, but students must design a persistent data format and keep the working directory, staging area, and commit history consistent.

## 边界条件 / Edge cases

- 重复 init 应报错，不能破坏已有仓库 / Repeated init must not destroy an existing repo.
- 空暂存区不能提交 / Empty staging area cannot be committed.
- checkout 的文件必须存在于当前提交 / checkout requires the file in the current commit.
- 提交 uid 必须与存储内容哈希一致，否则读不回来（开发中真实踩过这个坑）。
  *Commit uid must equal the hash of stored content, or it can't be read back (a real bug we hit).*

## 明确不做 / Non-goals

- 不实现分支合并、rebase、远程仓库 / No branch merge, rebase, or remotes.
- 不实现真正的 Git 对象压缩与索引格式 / No real Git object compression or index format.

## 验收 / Acceptance

- [x] init 创建 .gitlet 结构
- [x] add + commit 两次，log 显示 3 个提交（含 initial）
- [x] status 显示当前分支与 head
- [x] checkout 把被改坏的文件恢复为 HEAD 版本（内容的确恢复为 'hello gitlet\n'）
