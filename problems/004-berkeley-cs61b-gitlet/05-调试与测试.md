## 输出解读 / Reading the output

- 三次提交按 newest-first 排列：second → first → initial，符合 log 语义。
- 提交 uid（如 `828f05d`）是内容哈希，改一个字节就会变——这是内容寻址的直接体现。
- checkout 后的内容 `'hello gitlet\n'` 与第二次提交时写入的内容完全一致。

## 失败案例与排查 / Failures and debugging

| 症状 / Symptom | 原因 / Cause | 修复 / Fix |
|---|---|---|
| `FileNotFoundError: objects/<hash>` | `Commit.__post_init__` 算 uid 用 4 元组，`_save_commit` 存的是 5 元组（带 `"commit"` 标签），两处哈希不一致 / two different serializations produced different hashes | 统一用 `Commit._serialize()` 计算哈希；`_save_commit` 加 assert / unified serialization + assertion |
| 重复 init 冲掉历史 | 缺少存在性检查 / missing existence check | init 开头检查 HEAD 是否存在 / check HEAD before init |
| checkout 内容带 `blob:` 前缀 | blob 存储时加了类型前缀但读取未去掉 / type prefix not stripped | checkout 时去掉前缀 / strip the prefix |

> **English:** The first failure is the most instructive: content-addressable storage has a single source of truth for serialization. We fixed it by making `uid = sha1(self._serialize())` the one canonical rule.
