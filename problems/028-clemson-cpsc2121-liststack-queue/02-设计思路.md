# 02 · 设计思路 / Design

## 三层容器：List 是底座 / List is the foundation

栈和队列都是"受限制的表"——只暴露一端的 List。这是经典教学结构：**先造 List，再用组合包出 ADT**。upstream 的 ListStack 内部持有一个 `List<T> stack`（组合而非继承，ADT 的正确姿势）。

> **English:** Stack and queue as *restricted views* of a list — composition, not inheritance, is the right shape for ADTs.

## 规格即注释 / Comments as executable spec

接口注释写明："getFirst on empty returns T()"——这不是建议，是**可测的合同**。upstream 学生实现直接解引用 `start->value`（崩溃）——审阅者要拿注释当测试断言来读。
*Read interface comments as test assertions; that's how the five defects were found.*

## 修复版的边界哲学 / The fixed version's boundary philosophy

- 空容器访问 → 返回 `T()`（按接口注释）
- 越界 `getAt(j)` → 返回 `T()`
- 空容器 remove → no-op 不崩溃
- `size()` 补上缺掉的 `return`（UB → 良定义）

与 025（UCI）的 `std::optional` 语义对照：这是 C++98 时代的"哨兵值"方案——07 章有重构实验。
