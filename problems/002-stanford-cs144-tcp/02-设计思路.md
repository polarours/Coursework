# 02 · 设计思路 / Design rationale

## 整体架构 / Architecture

```text
 上层字节流 ──▶ [TCPSender] ──Segment──▶ [TCPReceiver] ──▶ 重组字节流
                   │                          │
          滑动窗口/重传/退避          ackno / window / SYN-FIN
                   ◀──────── ACK ─────────────┘
```

每层只依赖下层的接口，这正是能逐层测试的原因。
Each layer depends only on the interface below it — which is why it can be tested in isolation.

> **English:** Keep the abstraction boundary strict: the sender never reads the receiver's buffer directly, and the receiver never knows about retransmission. This is what makes a complex protocol testable.

## 关键决策 / Key decisions

| 决策 / Decision | 选择 / Choice | 理由 / Why |
|---|---|---|
| 序列号运算 / Seqno arithmetic | 全程用 `wrap_add` / `wrap_sub` | 32 位回绕是 TCP 的固有属性，必须用模运算 / wraparound is intrinsic to TCP |
| 重组存储 / Reassembly storage | `dict[index] -> byte` | 稀疏乱序数据用字典最直接；教学版不优化内存 / sparse out-of-order data maps naturally to a dict |
| 时钟 / Clock | 虚拟时钟 `tick(ms)` | 重传测试确定、快速、无 sleep / deterministic and fast retransmission tests |
| 窗口 / Window | 初始 4 字节的小窗口 | 便于在测试里观察窗口滑动与 ACK 边界 / small window makes sliding visible in tests |
| 零窗口 / Zero window | `max(window, 1)` | 防止发送端永久停死 / prevents sender deadlock |
| 退避 / Backoff | 每次超时 RTO ×2 | 标准 TCP 行为，测试可观测 10→20→40 / standard TCP behavior, observable in tests |

## 备选方案 / Alternatives

- **用真实的 `socket` 和时间 sleep**：更贴近真实，但测试慢且不稳定；教学版用虚拟时钟。
  *Real sockets and sleeps are closer to production but make tests slow and flaky.*
- **用数组而不是字典存重组缓冲**：连续数据快，但乱序稀疏时会浪费大量空间。
  *An array is faster for contiguous data but wasteful for sparse out-of-order data.*
- **用滑动窗口协议 GBn 而不是 SR**：CS144 更接近选择重传；我们按 SR 教学。
  *Go-Back-N is simpler; CS144 is closer to selective repeat, which we teach.*

> **English:** The most important mental model: **sequence number = byte position in the stream**, not a packet counter. SYN and FIN occupy positions too. Getting this wrong causes almost every off-by-one bug in TCP labs.
