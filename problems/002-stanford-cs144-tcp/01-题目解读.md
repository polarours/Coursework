## 需求概述 / Requirements

CS144 的实验让学生从零构建一个 TCP 实现：从字节流开始，逐层加入重组器、接收端、发送端，最终得到能收发数据的 TCP 连接。本项目聚焦前四个最核心的层：

CS144's labs build a TCP implementation from scratch, layer by layer. Our walkthrough focuses on the four most instructive layers:

1. **ByteStream / 字节流**：有容量限制的缓冲，writer 写入，reader 读取。
   *A capacity-limited buffer with a writer and a reader.*
2. **Reassembler / 重组器**：把乱序、重复、重叠到达的子串拼接成连续字节流。
   *Stitch out-of-order, duplicate, overlapping substrings into a contiguous stream.*
3. **TCPReceiver / 接收端**：处理 SYN/FIN，计算 32 位回绕的确认号 ackno 与接收窗口。
   *Handle SYN/FIN, compute 32-bit wrapping acknowledgements and the receive window.*
4. **TCPSender / 发送端**：滑动窗口、超时重传、指数退避。
   *Sliding window, retransmission timeout, exponential backoff.*

> **English:** The pedagogical genius of CS144 is the layer stack: each lab produces a component with a clean interface, so students can test one idea at a time before composing them.

## 输入与输出 / Input and output

- 接收端输入：`Segment(seqno, payload, syn, fin)`；输出：重组后的字节流 + ackno + window。
  *Receiver input: a segment; output: reassembled stream + ackno + window.*
- 发送端输入：上层字节流；输出：待发送的段序列；接收 ACK 后更新窗口。
  *Sender input: an outgoing byte stream; output: segments to send, updated by ACKs.*

## 边界条件 / Edge cases

- **序列号回绕**：seqno 是 32 位无符号整数，接近 2^32 时会回绕到 0。
  *Sequence numbers wrap at 2^32.*
- **SYN/FIN 占序列号**：SYN 和 FIN 各消耗一个序列号，但不携带数据。
  *SYN and FIN each consume one sequence number without data.*
- **乱序与重叠**：后发的数据可能先到；重复数据必须忽略；重叠部分不能重复计数。
  *Out-of-order arrival, duplicates, and overlaps must all be handled.*
- **零窗口**：接收窗口为 0 时发送端不能停死，要发探测报文。
  *A zero window must not deadlock the sender; send probe segments.*

## 明确不做 / Non-goals

- 不实现拥塞控制（CS144 Lab 4/5 的内容，见 07 延伸练习）/ No congestion control.
- 不实现真实 Socket 和网络层；用直接调用传递 Segment。
  *No real sockets; segments are passed by direct call.*
