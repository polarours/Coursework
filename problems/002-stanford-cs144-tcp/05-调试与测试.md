## 输出解读 / Reading the output

- `duplicate_bytes=3`：重叠插入的 `cde` 中有 3 字节已被覆盖，正确忽略。
  *Three bytes of the overlapping insert were already assembled and correctly ignored.*
- `tick(9) -> timeouts=0` 与 `tick(11) -> timeouts=1`：RTO=20 时，9ms 不触发、累计 20ms 触发——验证了退避边界。
  *With RTO=20, 9 ms doesn't fire while 11 ms (cumulative 20) does — verifies the backoff boundary.*
- `final flight` 中 FIN 段 seqno=11、payload 为空：FIN 占一个序列号但不带数据。
  *The FIN segment has seqno=11 and empty payload — FIN consumes a seqno without data.*
- 端到端 4 个段送达 19 字节 + SYN/FIN：窗口 8、每次 ACK 推进，符合预期。

## 失败案例与排查 / Failures and debugging

以下都是**开发过程中真实遇到的错误**，不是假设：
These are **real errors encountered during development**, not hypotheticals:

| 症状 / Symptom | 原因 / Cause | 修复 / Fix |
|---|---|---|
| `wrap_add(2^32-5, 10)` 断言失败（期望 4）| 测试算错：−5+10 = 5，不是 4 / test math was wrong | 修正断言为 5 / fixed the assertion |
| 接收端得到 `hellorld` | 测试数据重叠：`world`@3 与 `hello`@0 在 index 4 冲突 / test data overlapped | 改为 `world`@5，无重叠 / moved world to index 5 |
| 第二批数据期望 `def` 实际 `defg` | SYN 确认后窗口空出 4 字节（不再被 SYN 占 1）/ after SYN ACK, full 4-byte window is free | 修正期望为 `defg` / fixed expectation |
| 最终 ACK 被忽略 | ACK 超过了当前 `next_seq`（还没发完剩余数据）/ ACK exceeded `next_seq` | 分两轮：先 ACK 已发段，再发剩余+FIN / two-phase ACK |

> **English:** All six tests passed. Notable measurements: the reassembler counted 3 duplicate bytes from the overlapping insert; RTO backoff fired at cumulative 20ms but not at 9ms; and the FIN segment consumed seqno 11 with an empty payload. Three development failures were real test-design errors (off-by-one in the wraparound assertion, overlapping test data, and a miscalculated final ACK), all corrected and documented.
