# 05 · 调试与测试 / Debugging and testing

## 两层测试，两种信任 / Two layers, two kinds of trust

官方 starter 给了 74 个输入文件，但**没有给期望输出**——期望输出由 `sampledecomment` 生成，而那个二进制是 ARM 架构的，在 x86 机器上跑不了。这就逼出一个设计问题：怎么在没有权威 oracle 的情况下验证实现？

本项目用两层，各自回答不同的问题：

| 层 | 数据来源 | 回答的问题 |
|---|---|---|
| 金标准 | 题面表格里的例子，逐字节抄录 | 实现是否符合 Princeton 的**文字规定**？ |
| 交叉验证 | 官方 74 个输入 + 独立 Python oracle | 实现对**边界组合**的处理是否自洽？ |

第一层是权威的：每条都能在题面里找到出处。第二层不是权威，但覆盖面大，能抓到第一层没想到的组合。

> **English:** The spec examples are authoritative but sparse; the 74 starter files are broad but have no published answers. Layer one checks the rules, layer two checks coverage — and only layer two found the trailing-slash bug.

## 金标准层 / The golden layer

```python
GOLDEN = [
    ("single-line comment replaced by one space",
     "abc/*def*/ghi\n", "abc ghi\n", "", 0),
    ...
]
```

每条是 `(名字, 输入, 期望 stdout, 期望 stderr, 期望退出码)`。比较的是**四元组**，不是只比 stdout——因为 `Error: line 2:` 这种消息和退出码同样是判定标准的一部分。

38 条里有 32 条直接来自题面表格，另外 6 条是题面没列、但属于合理边界的：

- 空输入
- 只有 `/**/`
- 注释在文件开头
- 两个相邻注释
- 文件以孤立 `/` 结尾
- 文件以 `/*` 结尾

后两条是修 bug 之后补的回归用例。

## 独立 oracle / The independent oracle

```python
def oracle(text):
    """Index-based scan, not a streaming automaton."""
    out = []
    i, n = 0, len(text)
    while i < n:
        if text.startswith("/*", i):
            out.append(" ")          # comment collapses to one space
            i += 2
            while i < n:
                if text.startswith("*/", i):
                    i += 2
                    break
                if text[i] == "\n":
                    line += 1
                    out.append("\n")
                i += 1
            continue
        if text[i] in "\"'":
            # 整体吞掉一个字面量，处理转义
            ...
```

它与 C 实现**结构不同**：C 是逐字符流式状态机，oracle 是索引跳跃扫描。相同的错误很难在两种结构里同时出现——这是交叉验证有效性的前提。

如果 oracle 抄了实现的思路（比如也写成 DFA），那它只是在验证“我两次写了同样的 bug”。

## 实际抓到的 bug / The bug this found

`04falsecommentstart7.txt` 的内容是：

```
This is line one.
This is line two./
```

文件以孤立斜杠结尾。C 实现输出：

```
This is line one.
This is line two.
```

**斜杠丢了。** 原因：读到 `/` 时进入 `ST_SLASH`，然后 `getchar()` 返回 `EOF`，主循环退出。此时状态是 `ST_SLASH`，但 EOF 处理只检查了 `ST_COMMENT`/`ST_COMMENT_STAR`，斜杠从未被写出。

修复：

```c
if (ctx.state == ST_SLASH) {
    putchar('/');               /* trailing slash with nothing after it */
}
```

这个 bug 的教训是：**状态机在 EOF 时可能持有未提交的输出**。每个状态都要问一遍“如果现在结束，还欠什么”。金标准层没抓到它，因为题面的例子都以换行结尾，没有“斜杠 + EOF”这种形状。

## oracle 自己的 bug / The oracle's own bug

第一次运行，金标准 36/36 全过，oracle 层 15 个失败，全部集中在多行注释。看差异：

```
expected: "abc \njkl\n"
got:      "abc\n jkl\n"
```

空格和换行的顺序反了。原因在 oracle 里：

```python
while i < n:
    ...
    out.append("\n")
    i += 1
out.append(" ")          # ← 太晚了
```

空格应该在进入注释时立刻追加，而不是在注释结束后。修好之后 74/74 通过。

值得记下来的是：**失败的一方不一定是被测对象**。当时的判断依据是“金标准 36 条全过”——如果 C 实现错了，金标准不可能全过。先确认哪一方可信，再改代码，否则会把正确的实现改坏。
