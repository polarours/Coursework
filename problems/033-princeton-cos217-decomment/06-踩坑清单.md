# 06 · 踩坑清单 / Pitfalls

## 1. 重处理字符时重复计数行号 / Double-counting the newline

主循环里 `again = 1` 会让同一个字符再走一遍。如果行号递增写在循环体内无条件执行，那么 `/\n` 这种输入（斜杠后面跟换行）会让换行被数两次，后续所有“未终止注释在第几行”的报错都偏大。

正确做法是用 `fresh` 标记：

```c
fresh = 1;
do {
    again = 0;
    if (fresh && c == '\n') ctx.line++;
    fresh = 0;
    ...
} while (again);
```

> **English:** A reprocessed character must not advance the line counter twice; a `fresh` flag distinguishes the first pass from the replay.

## 2. EOF 时忘记提交待输出字符 / Forgetting to flush at EOF

见 05 章。`ST_SLASH` 是一个“已消费输入但未产出输出”的状态，EOF 必须把它补出来。同类问题还会出现在任何“缓冲一个字符再决定”的设计里。

自检方法：对每个状态问一句“如果现在 EOF，输出应该是什么”。

| 状态 | EOF 时应做 |
|---|---|
| NORMAL | 无 |
| SLASH | 输出 `/` |
| COMMENT / COMMENT_STAR | 报未终止注释 |
| STRING / STRING_ESC | 无（题面允许未终止字面量） |
| CHARLIT / CHARLIT_ESC | 无 |

## 3. 把注释空格放到换行之后 / Emitting the space after the newlines

多行注释的输出顺序是**先空格后换行**：

```
abc/*def
ghi*/jkl
```
→
```
abc 
jkl
```

不是 `abc\n jkl`。这个顺序错误在肉眼检查时几乎看不出来（两者都只差一个不可见字符的位置），但会让所有多行注释用例失败。本项目写 oracle 时就犯了这个错，15 个用例同时红。

## 4. 转义状态里仍然检查引号 / Checking the quote inside an escape state

```c
case ST_STRING_ESC:
    putchar(c);
    return ST_STRING;      /* 不要在这里判断 c == '"' */
```

`"a\"b"` 里被转义的 `"` 不能结束字符串。如果 `ST_STRING_ESC` 也写一遍 `if (c == '"') return ST_NORMAL;`，这个字符串会在中间被截断，后面的 `/*` 就被当成注释了。

## 5. 用 `fgets` 按行读 / Reading line by line with a fixed buffer

```c
char buf[1024];
while (fgets(buf, sizeof buf, stdin)) { ... }   /* 错 */
```

两个问题：超长行被截断（违反“任意长度”要求）；注释跨行时状态要跨 `fgets` 调用保持，代码会变得别扭。逐字符处理两个问题都不存在。

## 6. 认为 `//` 也是注释 / Treating `//` as a comment

题面明确是 C90：`abc//def` 原样输出。如果按现代 C 的直觉实现，`abc//def` 会变成 `abc `，官方用例 `02singlelinecomment*.txt` 会大量失败。

## 7. 把 `*/` 的识别写成“看到 `*` 就结束” / Closing on a single star

`/* a * b */` 中间那个孤立星号不是结束符。必须区分 `ST_COMMENT`（刚读到普通字符）与 `ST_COMMENT_STAR`（刚读到星号，下一个字符决定是否结束）。

## 8. 假设测试 oracle 一定对 / Assuming the oracle is the source of truth

交叉验证的价值来自“两个实现独立”。一旦发现分歧，先判断哪一方与**权威规格**一致，再改代码。本项目第一次跑 oracle 层时 15 个失败，如果直接改 C 实现去迁就 oracle，就会把正确的实现改坏。

判断顺序应该是：

1. 有没有权威规格？→ 用规格裁决
2. 规格没覆盖？→ 手工构造最小用例，逐步缩小分歧
3. 两边都“看起来对”？→ 检查是否共享同一个错误假设（例如都以为空格在换行后）

## 9. 忽略 stderr 与退出码 / Comparing only stdout

`abc/*def` 的 stdout 是 `abc `（带一个空格），退出码是 1，stderr 有一行消息。只比 stdout 的测试会漏掉后两项，而它们在评分里各占一部分。测试函数应返回并比较三元组 `(stdout, stderr, exit_code)`。
