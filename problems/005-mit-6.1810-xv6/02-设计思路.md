# 02 · 设计思路 / Design rationale

## 整体架构 / Architecture

```text
 调度器                              伙伴分配器
 ─────────                           ──────────
 Proc(pid, arrival, burst)           64 字节初始块
   │                                   │
   ├─ FCFS  (按到达排序)               ├─ alloc(7) → 分裂成 8
   ├─ RR    (时间片轮转)               ├─ alloc(8) → 8
   └─ MLFQ  (多级反馈队列)             └─ free → 与伙伴合并成 16
```

> **English:** Both topics share a theme: a simple invariant applied repeatedly yields complex-looking behavior. FCFS is just "sort by arrival"; buddy allocation is just "split powers of two, merge equal free neighbors."

## 关键决策 / Key decisions

| 决策 / Decision | 选择 / Choice | 理由 / Why |
|---|---|---|
| 等待时间 / Wait time | 用 `last_run` 与 `origin` 两个字段分别记录 | 重新入队时 arrival 语义会混淆；拆开后清晰且正确 / avoid reusing `arrival` for a different meaning |
| RR 时间片 / Quantum | 2（测试用）| 小时间片便于观察多次调度 / small quantum makes multiple dispatches visible |
| MLFQ 层级 / Queues | 3 层，低层时间片翻倍 | 经典 MLFQ 设计 / classic MLFQ design |
| 分配策略 / Alloc | 2 的幂向上取整 + 首次适应 | 伙伴系统的前提 / prerequisite for buddy coalescing |
| 合并 / Coalesce | 相邻、等大、都空闲才合并 | 伙伴的定义 / definition of buddies |

## 备选方案 / Alternatives

- **用隐式空闲链表（CSAPP malloc lab 风格）**：见 006 题；伙伴系统更适合教学"分裂/合并"。
  *See problem 006 for implicit free lists; buddy system better illustrates split/merge.*
- **实现完整 xv6 内核**：需要 QEMU、交叉编译与真实硬件知识，超出自包含学习库范围。
  *A full kernel needs QEMU and toolchains, beyond a self-contained repo.*

> **English:** We deliberately kept the scheduler deterministic (no random I/O) so the printed metrics are reproducible — a hard requirement of this project's evidence discipline.
