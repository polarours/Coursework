# 04 · 正确性与复杂度 / Correctness and complexity

## 不变量 / Invariants

1. **周转 = 等待 + CPU / Turnaround = wait + burst**：对任一完成进程成立。
   *Holds for every finished process.*
2. **等待单调 / Wait monotonicity**：进程的 `wait_time` 只增不减，且跨多次调度累计。
   *`wait_time` only increases, accumulated across dispatches.*
3. **伙伴合并条件 / Coalesce condition**：仅当相邻、等大、都空闲时合并。
   *Only adjacent, equal-sized, both-free blocks merge.*
4. **2 的幂 / Power of two**：分配的块大小总是 2 的幂。
   *Allocated blocks always have power-of-two sizes.*

> **English:** The `turnaround = wait + burst` identity is a good self-check: in our output, FCFS P1 has wait 0, burst 5, turnaround 5; averages 3.33 and 8.33 differ by exactly 5 (the burst).

## 证明思路 / Proof sketch

**为什么 RR 的平均等待比 FCFS 高？/ Why is RR's average wait higher than FCFS?**

实测：FCFS avg_wait=3.33，RR avg_wait=6.00。这不是 bug——RR 用更多的上下文切换换取更好的响应公平性；在本 workload 下长进程 P3（burst 7）被反复切换，累计等待更长。**平均等待时间的最优算法是 SJF（最短作业优先），不是 RR。**

Measured: FCFS 3.33 vs RR 6.00. This is *not* a bug — RR trades more context switches for fairness. SJF minimizes average waiting time, not RR.

**伙伴合并的正确性 / Correctness of buddy coalescing**

只有地址相邻、大小相等、均为空闲的两块才可能是"伙伴"。重复扫描直到没有可合并对，保证空闲列表规范化。实测 free(8) 后 free(0) 得到 (0,16)。

## 复杂度 / Complexity

| 操作 / Operation | 时间 / Time | 空间 / Space |
|---|---|---|
| FCFS | O(n log n)（排序）| O(n) |
| RR | O(total_burst / quantum) | O(n) |
| MLFQ | O(total_burst / quantum) | O(n) |
| buddy alloc | O(块数) / O(blocks) | O(块数) |
| buddy free + 合并 | O(块数²) 最坏 / O(blocks²) worst | O(块数) |
