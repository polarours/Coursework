# 06 · 踩坑清单 / Pitfalls

## 1. 字段语义混淆 / Misleading field semantics

- 症状 / Symptom：`arrival` 字段在重新入队时被改写为"上次运行结束"时刻，读代码者极易误解。
- 修复 / Fix：拆分为 `origin`（永不变）与 `last_run`（每次调度更新）。
- 说明 / Note：重构前后数字相同——这是可维护性问题，不是计算错误。我们如实记录。

> **English:** Honest debugging matters: when a refactor doesn't change the numbers, say so. The bug was in *clarity*, not arithmetic.

## 2. 误把 RR 高等待当作 bug / Mistaking RR's higher wait for a bug

- 症状 / Symptom：看到 RR avg_wait 6.00 > FCFS 3.33，怀疑实现错了。
- 真相 / Truth：SJF 才最小化平均等待；RR 优化的是响应公平。这是理论预期。

## 3. 伙伴合并条件过宽 / Over-permissive coalescing

- 症状 / Symptom：合并后出现超过 64 字节的块或地址不连续。
- 修复 / Fix：严格检查 `相邻 && 等大 && 都空闲`。

## 4. 忽略 double-free / Ignoring double-free

- 症状 / Symptom：同一块被释放两次，空闲列表出现重复项。
- 修复 / Fix：`free()` 检查 `not b.free`，否则返回 False（测试中已验证）。

## 5. 时间片未用尽就降级 / Demoting before quantum exhausted

- 症状 / Symptom：MLFQ 行为与理论不符。
- 修复 / Fix：仅当 `remaining > 0`（即用尽时间片）时才降级。
