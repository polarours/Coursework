# 03 · 逐步实现 / Step-by-step implementation

## 阶段 1 / Stage 1 — 进程模型

为每个进程记录 `origin`（原始到达时刻）与 `last_run`（上次运行结束时刻）——两个字段分开是关键。

Track both `origin` (original arrival) and `last_run` (last dispatch end) — keeping them separate is crucial.

```python
@dataclass
class Proc:
    pid: int; arrival: int; burst: int
    last_run: int = 0; origin: int = 0
    def __post_init__(self):
        self.remaining = self.burst
        self.last_run = self.arrival
        self.origin = self.arrival
```

验证 / Verify: 三种算法都能跑出结果。

## 阶段 2 / Stage 2 — FCFS

按到达时间排序，非抢占；`wait = start - origin`。

Sort by arrival; non-preemptive.

验证 / Verify: order=[1,2,3]，avg_wait=3.33（真实输出）。

## 阶段 3 / Stage 3 — RR 与等待累计

每次被调度时 `wait_time += t - last_run`，运行后更新 `last_run = t`。

```python
p.wait_time += t - p.last_run
run = min(quantum, p.remaining)
t += run
p.last_run = t
```

验证 / Verify: RR 时间线 `[1:2, 2:2, 3:2, 1:2, 2:1, 3:2, 1:1, 3:2, 3:1]`——每个进程被多次调度。

## 阶段 4 / Stage 4 — MLFQ

三层队列，用完时间片降级；低层时间片翻倍。

Three queues; demote on quantum exhaustion; lower queues get longer quanta.

验证 / Verify: MLFQ 的 avg_wait=5.33、avg_turnaround=10.33，介于 FCFS 与 RR 之间。

## 阶段 5 / Stage 5 — 伙伴分配器

`alloc(7)` 向上取整到 8；把 64 分裂成 8+8+16+32 中的 8 分配出去。释放时若相邻伙伴都空闲且等大，则合并。

Round 7 up to 8; split 64 into powers of two; coalesce equal-sized free neighbors on free.

```python
if a.free and b.free and a.start + a.size == b.start and a.size == b.size:
    a.size *= 2
    del self.blocks[i + 1]
```

验证 / Verify: free(8) 后再 free(0)，空闲列表中出现 (0,16) —— 合并成功。

> **English:** The double-free guard (`if not b.free`) is a small detail with big consequences: without it, a single buggy free could corrupt the entire free list.
