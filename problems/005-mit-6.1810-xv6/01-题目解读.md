## 需求概述 / Requirements

MIT 6.1810（原 6.828）的 xv6 实验让学生修改一个教学用 Unix 内核。本项目选取其中最能锻炼系统思维的两个主题，做成可运行的模拟器：

MIT 6.1810's xv6 labs ask students to modify a teaching Unix kernel. We pick the two most instructive topics and build runnable simulators:

1. **进程调度 / Process scheduling**：实现 FCFS、时间片轮转（RR）、多级反馈队列（MLFQ），并比较平均等待与周转时间。
   *Implement FCFS, round-robin, and MLFQ; compare average waiting and turnaround times.*
2. **内存分配 / Memory allocation**：实现伙伴分配器（buddy allocator）——按 2 的幂分裂、释放时与伙伴合并。
   *Implement a buddy allocator: split into powers of two, coalesce with buddies on free.*

> **English:** xv6 labs are famous for forcing students to reason about concurrency and kernel data structures. Our simulator keeps the algorithmic core (scheduling policy, buddy splitting/merging) while dropping the hardware-specific baggage.

## 输入与输出 / Input and output

- 调度输入：进程列表（pid、到达时间、CPU 突发时间）；输出：调度顺序、时间线、平均等待/周转时间。
  *Scheduling input: process list; output: order, timeline, average wait/turnaround.*
- 分配器输入：alloc(size) / free(start)；输出：分配地址、空闲块列表。
  *Allocator input: alloc/free calls; output: address and free list.*

## 边界条件 / Edge cases

- 进程到达时间不同 → 调度器要正确处理空闲 CPU。
  *Different arrival times → scheduler must handle idle CPU.*
- RR 时间片用尽但进程未结束 → 重新入队；等待时间要跨多次调度累计。
  *RR quantum exhausted → requeue; waiting time must accumulate across dispatches.*
- 分配大小不是 2 的幂 → 向上取整到下一个 2 的幂。
  *Non-power-of-two sizes → round up to the next power of two.*
- 重复释放同一块 → 应返回失败（double-free 检测）。
  *Double free → return failure.*

## 明确不做 / Non-goals

- 不实现真实的 xv6 内核、陷阱、页表或中断；这是算法层模拟。
  *No real xv6 kernel, traps, page tables, or interrupts — algorithmic simulation only.*

## 验收 / Acceptance

- [x] 三种调度算法输出调度顺序与平均指标
- [x] RR 与 MLFQ 的等待时间跨多次调度正确累计
- [x] 伙伴分配器：alloc(7)→0, alloc(8)→8, alloc(4)→16（2 的幂对齐）
- [x] 释放后与伙伴合并：free(8) 后再 free(0)，得到 16 字节的合并块 (0,16)
