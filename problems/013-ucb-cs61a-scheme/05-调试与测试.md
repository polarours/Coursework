# 05 · 调试与测试 / Debugging and testing

```text
[scheme] (+ 1 2 3) => 6

[scheme] (if (< 1 2) 100 200) => 100
[scheme] (car (list 1 2 3)) => 1
[scheme] factorial(5) = 120

--- PASS: test_scheme
```

## 输出解读 / Reading the output

- 闭包测试 `add5(3)=8` 证明 lambda 捕获了定义时的环境（x=5）——这是解释器最微妙也最精彩的部分。

> **English:** All tests passed. Arithmetic, conditionals, and list primitives returned the expected values. The closure result add5(3)=8 is the most significant: it shows the returned lambda still knows x=5 from its defining environment, which is the subtle heart of interpreter design.

## 失败案例与排查 / Failures and debugging

本实现测试一次通过，未遇到真实失败；下表为根据解释器语义推导的**预防性**易错点（非实测 bug）。
The implementation passed on the first run; no real failure occurred. The table lists **preventive** pitfalls derived from interpreter semantics, not observed bugs.

| 症状 / Symptom | 原因 / Cause | 预防 / Prevention |
|---|---|---|
| if 两个分支都被求值 / Both branches evaluated | 提前求值全部参数 / eager argument evaluation | handle special forms before generic apply |
| 变量找不到 / Unbound variable | 环境链方向错误 / wrong environment chain direction | lookup walks toward parent |
| 闭包丢失捕获值 / Closure loses captured value | lambda 捕获了调用时环境 / captures call-time env | capture the defining env object |
